Why I Moved from GitHub Pages to Cloudflare Pages

Published: Nov 19, 2026

If you've been following my journey, I originally hosted this site on GitHub Pages. It was free, easy to set up, and perfect for static HTML files. However, I recently hit a wall: Bandwidth Limits and Caching.

GitHub Pages has a soft limit of 100GB per month. For a portfolio, that's fine. But for my streaming site with heavy movie posters, it became a concern. Also, whenever I updated my code, I had to manually purge the cache on Cloudflare if I was using their proxy.

Enter Cloudflare Pages.

I moved my repositories here and immediately noticed the difference. Unlimited bandwidth, automatic cache invalidation, and a global edge network that serves my site faster. Here's how I did it:

1. Connect GitHub Repo to Cloudflare Pages.
2. Set Build Command: "exit 0" (since it's static HTML).
3. Set Build Output Directory: "/".
4. Click Deploy. Done.

No more manual purging. No more bandwidth anxiety. Just fast, secure hosting.

Building an Interactive Python Terminal in the Browser

Published: Nov 15, 2026

One of my favorite features on this site is the Interactive Python Terminal. Many people ask, "How are you running Python in a browser without a backend?"

The answer is Pyodide. It's a port of CPython to WebAssembly (WASM). It allows you to run real Python code directly in the browser.

Here's the simplest way to get started:

<script src="https://cdn.jsdelivr.net/pyodide/v0.25.0/full/pyodide.js"></script>

<script>
  async function main() {
    let pyodide = await loadPyodide();
    // Run Python code
    pyodide.runPython(`
      print("Hello from Python!")
    `);
  }
  main();
</script>

It's a game-changer for educational platforms. You get the power of Python without needing a server.

Understanding JWT (JSON Web Tokens) in 5 Minutes

Published: Nov 10, 2026

If you've ever used a modern web app, you've probably encountered a JSON Web Token (JWT). It's the standard for authentication.

A JWT is just a string with three parts separated by dots: Header.Payload.Signature.

  • Header: Tells us the algorithm (like HS256).
  • Payload: The actual data (user ID, name, expiration date).
  • Signature: Used to verify the token hasn't been tampered with.

You can decode the Header and Payload easily using Base64Url decoding, which is why I built the JWT Decoder tool on my homepage.

Security Warning: Never store sensitive information in the Payload. It is only Base64 encoded, not encrypted. Anyone can read it.
